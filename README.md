## How it is checked

Every push runs [the proof check](.github/workflows/build.yml) on GitHub:

1. **Build**: every module compiles against Lean `v4.35.0` and Mathlib `v4.35.0`.
2. **Independent replay**: every module is re-checked by Lean's separate kernel checker.
3. **Axiom audit**: every named theorem depends only on `propext`, `Classical.choice` and
   `Quot.sound`. No `sorry`, no project axioms, no `native_decide`. The inventory is fixed in
   [`scripts/config.json`](scripts/config.json), so a theorem cannot silently disappear.
4. **False controls**: nine control files must fail to compile, for a mathematical reason: a false
   later-transmission equality and an unsafe mean-before-inversion inequality (together in
   `FalseControl.lean`), equal futures from equal instantaneous readouts, a positive same-spin pair
   density at coincidence, a response equality that drops the exterior self-energy term,
   nonnegativity of the Hall incremental form at `σ = 1`, `c = 3`, and four loop-wall controls
   (nitrogen's core opening called outside, carbon's inside, `Γ²` flipped in sign under reversal,
   and a wrong count of the eight outside steps).
5. **No warnings**: every library module also elaborates with warnings promoted to errors,
   `LEAN_PATH=.:$LEAN_PATH lean -DwarningAsError=true <module>.lean`, so an unused hypothesis, a
   `simp` argument that does nothing or a tactic that never runs fails the check instead of
   accumulating. The nine control files are excluded, since their whole purpose is to fail.

```bash
lake exe cache get
lake build
python3 scripts/verify.py
```

The loop-wall archive certificate is regenerated from the data with

```bash
python3 scripts/gen_archive_lean.py
```

On a machine that has a prebuilt Mathlib on `LEAN_PATH` and the modules' `.olean` files, the same
audit runs without `lake`: `LEAN_CMD=lean python3 scripts/verify.py`.
